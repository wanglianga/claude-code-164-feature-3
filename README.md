# 市民篮球场 · 预约拼场 / 照明计费 / 冲突调解 / 夜间噪声限制（移动端 H5 演示）

一个面向**手机现场操作**的单页应用：市民按场地、半场/全场、时间段、人数、是否拼场、是否需要夜间照明预约公共篮球场；队长邀请队员签到、散客申请拼场；管理员在后台看到每个时段的预约人数、实际到场、支付状态与冲突风险；社区工作人员处理噪声投诉、未成年人夜留与篮筐争议。所有费用变化、退款补偿、处罚记录都与具体规则条文（编号 R-xxx）一一关联、可点击查看。

**本期扩展（居民夜间噪声投诉 → 夜间限制）**：

- **噪声记录四要素聚合**：每次居民投诉都把「投诉时间、场地使用队伍、照明关闭时间、管理员/社区现场提醒（含实测分贝）」记在同一条噪声记录里，投诉人、处置过程与答复全程留痕（R-NOISE-1）。
- **多次违规 → 夜间限制**：按队长实名手机号归并同一球队 90 天内经现场核实的违规——累计 **2 次：后续 30 天夜间预约押金上浮 50%**（半场 50→75 元 / 全场 100→150 元）；累计 **3 次：30 天内只能预约 20:00 前结束的时段**（R-NIGHT-1）。
- **社区端效果评估**：事件页顶部「夜间限制效果」面板按球队对比**限制生效前 30 天与生效后至今的投诉核实数量**，含未核实投诉数与限制后最近关灯离场时间，直观回答"限制是否降低投诉"。
- **预约前规则明示**：受限队长在提交预约前即可看到**历史违规原因（逐条日期/分贝/关灯时间）与本次押金规则**；20:00 后时段对 L2 球队直接禁用。
- **队员同口径**：预约卡片、队员签到页、散客找拼场、现场看板都公示**平台统一结束（关灯离场）时间**（晚于场地静音截止的夜场按截止时间关灯，如 A 区 21:00、B 区/河滨 22:00），减少队长个人口头承诺与平台规则不一致。

技术栈：**Vue 3 + TypeScript + Vite + Naive UI**，纯前端 + 内置 mock 数据与响应式规则引擎，无需后端即可完整演示全部流程。

## 本地启动

### 方式一：Node 直接运行

```bash
npm install
npm run dev        # http://localhost:5173 （已监听 0.0.0.0，手机局域网可访问）
```

> 若 npm 全局缓存目录存在 root 属主文件（部分沙箱环境），可改用独立缓存：
> `npm install --cache /tmp/npm-cache-164`

### 方式二：Docker / Compose 一键启动（交付物内置）

```bash
docker compose up -d --build      # 构建并后台启动
# 打开 http://localhost:8080
docker compose logs -f
docker compose down               # 停止
```

或仅用 Docker：

```bash
docker build -t court-booking-night .
docker run --rm -p 8080:80 court-booking-night
```

镜像为多阶段构建：Node 20 构建静态产物 → nginx 1.27 托管（含 SPA history 回退），容器内置健康检查。

其他命令：

```bash
npm run build      # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
npm run smoke      # 夜间限制/噪声记录/照明计费冒烟断言（esbuild 打包后在 Node 执行）
```

建议用浏览器 DevTools 切换到手机视口（如 iPhone 390×844）体验；页面最大宽度 480px 居中。

## 建议的验证路径（均为可在页面上实际操作的流程）

1. **预约**：场地预约 → 选择 B区/河滨球场 → 半场/全场、时段（已满/故障/维修的半场自动禁用）、人数（低于建议下限会提示拼场）、勾选接受拼场与夜间照明 → 看到押金与预估费用 → 提交后在「我的队伍」出现签到码。
2. **夜间限制告知（预约前）**：场地预约 → 选任一片场地 → 队长姓名填 `高夜`（或手机号 `131****5566`）→ 提交前出现红色 L2 告知卡（历史 3 次违规逐条原因、押金 50→75 规则）；20:00–22:00 时段下拉显示"夜间限制：仅可约 20:00 前结束"且禁用；改为 18:00–20:00 可正常提交，支付押金为 75 元。填 `鲍越` 可验证 L1（不禁时段、仅押金上浮）。
3. **队员可见统一结束时间**：切到队长陈晨 → 我的队伍 → B001 卡片显示"统一结束（关灯离场）时间 20:00"；点"签到管理"抽屉顶部同样公示。散客王同学"找拼场"卡片也显示各队统一关灯离场时间。A 区 20:00–22:00 夜场名义 22:00 结束但平台统一 21:00 关灯（静音截止），看板/卡片同口径。
4. **噪声记录四要素 + 处置升级**：切到社区林芳 → 事件处置 → I-001：噪声记录卡聚合投诉时间（9/27 19:05）、使用队伍（散客联队周浩）、投诉人；处理前可"写入现场提醒（实测 74dB）""登记关灯时间 20:10"。点"首次劝导·办结（计 1 次违规）"后，散客联队累计 3 次 → 自动升级 L2，其进行中 B002 卡片出现夜间限制横幅（已付押金不追溯）。
5. **社区端看限制效果**：事件页顶部面板：合计核实违规限制前→后数量；夜鹰队显示"2 次核实 → 0 次核实（另有 1 条未核实），投诉核实下降 ✅"、限制后最近关灯 19:58；可展开历史违规原因。
6. **投诉不成立不计数**：对任意新建噪声投诉（现场上报或 I-001 处置区）点"现场未超标·投诉不成立"，记录标记未核实、不计违规、不触发限制，仍书面答复居民（R-FAIR-3）。
7. **队长签到与照明计费**：我的队伍 → B001 邀请队员、逐个签到；推进时钟，观察"还能打多久"、照明分钟数、实时金额（拼场 8 折、按签到人数平摊）；点「结束使用并关灯」按实际时长结算，关联噪声记录的关灯时间自动同步，押金余额退还。
8. **散客拼场**：切到王同学 → 拼场签到页对晨光队的申请显示"待处理"；切回队长**同意**后散客可凭码签到；队长拒绝时必须填写正当理由，否则产生 20 元资源占用费与信用扣分。
9. **迟到 / 爽约 / 超时**：把时钟推过某待开场场次开场 20 分钟，看板/后台出现「释放场地」（R-LATE-1）；对进行中场次持续推时过结束时间可见超时费 2 元/分钟、超 15 分钟可强制清场（R-OT-2）；B006 是已结算的超时案例。
10. **照明故障 / 下雨 / 篮筐维修 / 封场 / 现场看板 / 公平性解释**：I-005 三选一无责方案（R-LIGHT-3）；后台发布积水/恢复（R-WX-1）；B005 维修改约补偿（R-WX-2）；I-006 签发封场令仅中止 B009（R-SEAL-1）；看板公示半场使用者、签到码、剩余时间、争议判断指引；后台黄金时段固定队 ≤60% 配额条（R-FAIR-1~4）。

## 已执行的验证

- `npm run build`（含 `vue-tsc --noEmit` 全量类型检查）通过，产物输出到 `dist/`。
- `npm run smoke`：**28 项断言全部通过**（esbuild 打包 store+engine+mock 后在 Node 执行），覆盖：
  - 90 天窗口按队长手机号归并：周浩 2 次→L1、高夜 3 次→L2、鲍越 2 次→L1；未核实投诉不计违规；
  - 押金分级（半场 50→75、全场 100→150）、L2 的 20:00 时段禁用边界（20:00 可约/20:30 禁用）、L1 不禁时段；
  - 平台统一结束时间（河滨 21:00–22:30→22:00、A 区 20:00–22:00→21:00、静音截止前不变）；
  - 新预约自动写入限制快照/上浮押金/违规原因时间线；
  - I-001 首次劝导办结后噪声记录四要素（含现场提醒、关灯登记）齐全，散客联队升级 L2，进行中场次同步等级但已付押金不追溯；
  - 投诉不成立不计违规、不触发限制；
  - 社区效果统计：夜鹰队 L2 生效日 9/19，生效前 2 次核实、生效后 0 次核实（1 条未核实），趋势 down；
  - 照明实时计费回归（97 分钟 × 0.8 元 × 拼场 8 折 = 62.08 元，6 人均摊 ≈ 10.35 元/人）。
- `npm run dev` 启动后，用 `curl` 验证首页（HTTP 200、标题正确）以及全部 `src/**` 模块（含两个新组件）经 Vite 转换后均返回 200、无转换错误。
- 修复了一个既有缺陷：新建事件工单 ID 计数器前缀与 `nextId('I-')` 不匹配导致可能与 I-001 撞号。

说明：本项目为前端交互演示，支付、短信、真实定位、Docker 构建（当前环境无 Docker daemon）均为页面内模拟/配置交付；刷新页面会重置为初始演示数据。
