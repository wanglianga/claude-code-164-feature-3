# 市民篮球场 · 预约拼场 / 照明计费 / 冲突调解（移动端 H5 演示）

一个面向**手机现场操作**的单页应用：市民按场地、半场/全场、时间段、人数、是否拼场、是否需要夜间照明预约公共篮球场；队长邀请队员签到、散客申请拼场；管理员在后台看到每个时段的预约人数、实际到场、支付状态与冲突风险；社区工作人员处理噪声投诉、未成年人夜留与篮筐争议。所有费用变化、退款补偿、处罚记录都与具体规则条文（编号 R-xxx）一一关联、可点击查看。

**夜间噪声限制（本题扩展）**：附近居民连续投诉十点后噪声，社区/管理员在工单中把**投诉时间、使用队伍、照明关闭时间、现场提醒**四项一起留痕，并按球队累计：30 天内多次违规的球队，后续夜间预约**押金上浮**（半场 50→100 元 / 全场 100→200 元）或**限制最晚结束时间**（不晚于 21:00），第 4 次暂停夜间预约 30 天；社区端可回看**限制生效前后投诉量对比**，确认限制是否降低投诉。预约前页面向队长**公示历史违规原因与本次押金规则**；夜间场次的**结束时间、静音截止、到点自动关灯对每名队员公开可见**，减少队长个人承诺与平台规则不一致。

技术栈：**Vue 3 + TypeScript + Vite + Naive UI**，纯前端 + 内置 mock 数据与响应式规则引擎，无需后端即可完整演示全部流程。

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173 （已监听 0.0.0.0，手机局域网可访问）
```

## Docker 一键启动（无需本机 Node）

```bash
docker compose up --build -d     # 构建后访问 http://localhost:8080
docker compose logs -f court-booking-web
docker compose down              # 停止
```

多阶段 `Dockerfile`（node:20 构建 → nginx:1.27 托管 `dist/`，内含 SPA history 回退与 gzip）；也可单独 `docker build -t court-booking-web . && docker run -p 8080:80 court-booking-web`。

其他命令：

```bash
npm run build      # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
```

建议用浏览器 DevTools 切换到手机视口（如 iPhone 390×844）体验；页面最大宽度 480px 居中。

## 建议的验证路径（均为可在页面上实际操作的流程）

1. **预约**：场地预约 → 选择 B区/河滨球场 → 半场/全场、时段（已满/故障/维修的半场自动禁用）、人数（低于建议下限会提示拼场）、勾选接受拼场与夜间照明 → 看到押金与预估费用 → 提交后在「我的队伍」出现签到码。
2. **队长签到与照明计费**：我的队伍 → B001 晨光队 → 邀请队员、逐个签到；推进时钟，观察"还能打多久"、照明分钟数、实时金额（拼场 8 折、按签到人数平摊）；点「结束使用并关灯」按实际时长结算，押金余额退还。
3. **散客拼场**：切到王同学 → 拼场签到页对晨光队的申请显示"待处理"；切回队长**同意**后散客可凭码签到；也可找其他队伍新申请，队长拒绝时必须填写正当理由，否则产生 20 元资源占用费与信用扣分。
4. **迟到 / 爽约 / 超时**：B002 散客联队预置了迟到 23 分钟与无理由拒拼扣费；把时钟推过某待开场场次开场 20 分钟，看板/后台出现「释放场地」（R-LATE-1）；对进行中场次持续推时过 20:05 可见超时费 2 元/分钟、超 15 分钟可强制清场（R-OT-2）；B006 是已结算的超时案例。
5. **照明故障（I-005）**：事件页 → B区 H1 故障工单 → 管理员核验后由队伍三选一：等维修 / 改约（押金全退、优先排位）/ 全额退款，费用计时此前已自动冻结（R-LIGHT-3）。
6. **下雨地滑 / 篮筐维修**：后台「场地状态控制」可发布积水暂停/湿滑/恢复（R-WX-1）；B005 预置了篮筐紧急维修改约 + 5 元交通补偿案例（R-WX-2）；I-002 是已裁决的争抢篮筐工单（R-DISPUTE-1）。
7. **噪声投诉 / 未成年人夜留**：以社区工作人员身份处理 I-001（首次劝导 vs 24h 内第 2 次核实收 50 元，R-NOISE-1）、I-004（监护人接回登记，R-MINOR-1）。
8. **封场（I-006）**：管理员对河滨 H3/H4 的社区活动工单签发封场令 → 仅受影响的 B009 被中止、押金全退、可免费改约；同场地正在打球的 B003（H1/H2）不受影响；场地页/看板对应半场显示"封停"（R-SEAL-1）。
9. **现场看板**：任意身份都能看到每个半场当前使用者、签到码、到场人数、剩余/超时时间，以及争议时"预约码→时段比对→先到先得+信用分"的判断指引。
10. **公平性解释**：管理后台有黄金时段固定队 ≤60% 的配额条；规则页顶部给出改约优先级链（安全维修 > 已支付已签到 > 固定队 > 先到先得 > 信用分），每张被改约卡片（B005/B009 等）都有管理员说明与规则编号，解释"为什么是这一方被改约/限制"（R-FAIR-1~4）。
11. **夜间噪声限制（本题新增，R-NOISE-2 / R-NOISE-3）**：
    - **工单四要素留痕**：切到社区工作人员 → 事件处置 → I-001（噪声工单），填写/确认「投诉时间、照明关闭时间、管理员现场提醒、实测分贝」，点首次劝导或 24h 内第 2 次核实；卡片上出现四要素留痕块，处理中可看到该队历史夜间记录；二次核实时照明按填写时间关灯、停止计费。
    - **多次违规升级**：对同一球队连续办结 2 次（在同一工单上可重复演示：先"首次劝导"，工单办结后改由新噪声工单再次核实；或直接看预置夜猫子队 B011），第 2 次触发押金上浮、第 3 次限时段（≤21:00）、第 4 次暂停夜间预约。
    - **预约前提示队长**：场地预约 → 河滨公园灯光球场 → 选 20:00–22:00 夜间时段 → 点「填入『夜猫子篮球队』」，提交前出现历史违规原因清单与本次押金规则（半场 ¥100 / 全场 ¥200）；普通队仍为 ¥50/¥100。
    - **队员可见结束时间**：任意夜间场次的预约卡片、现场看板、散客"找拼场"列表都显示「平台结束时间 / 静音截止 / 到点自动关灯，队长口头延长无效」。
    - **社区端看效果**：事件处置页顶部「🌙 夜间限制效果回看」展示被限制球队生效前 14 天与生效后投诉数对比（下降 ✅ / 尚未下降），以及按日投诉趋势条。

## 页面与模块

```
src/
├─ App.vue                 手机外壳、顶栏角色切换、演示时钟、底部导航、通知
├─ types.ts                领域模型（场地/预约/队员/费用条目/事件工单/拼场申请…）
├─ store.ts                响应式状态 + 全部业务动作（预约/签到/拼场/照明结算/释放/封场/改约/处罚）
├─ data/
│  ├─ mock.ts              3 片场地、11 个预约、6 个事件工单、夜间噪声违规历史档案（覆盖题目全部情形）
│  └─ rules.ts             22 条规则条文（预约拼场/到场超时/照明/天气/争议/噪声含 R-NOISE-2/3/公平）
├─ lib/
│  ├─ engine.ts            规则引擎：实时照明计费（静音截止自动关灯）、迟到/超时、费用汇总、冲突风险、占用/释放、拼场正当性、夜间违规聚合/限制等级/押金/投诉效果
│  └─ ui.ts                标签页与规则跳转总线
├─ components/
│  ├─ BookingCard.vue      预约卡片：剩余时间、到场、实时照明费、费用变化、权益时间线、夜间结束时间全员公示条
│  ├─ RiskTag.vue          风险标签（点击展开原因）
│  ├─ RuleLink.vue         规则编号链接（跳到规则页并高亮）
│  └─ BottomSheet.vue      移动端底部抽屉
└─ pages/
   ├─ CourtsPage.vue       场地状况 + 预约表单（夜间公示结束时间、受限队历史违规原因与押金规则）+ 现场上报 + 今日占用
   ├─ MinePage.vue         队长（邀请/签到/拼场审核/照明/结算）与散客（签到码/找拼场含夜间结束时间/申请进度）
   ├─ BoardPage.vue        现场看板：谁在用、还能打多久、夜间结束/静音截止、释放/强制清场、争议判断指引
   ├─ AdminPage.vue        后台：时段维度人数/到场/支付/风险/夜间限制标签、场地控制、改约、公平性配额
   ├─ IncidentsPage.vue    事件工单：噪声四要素录入、历史违规、限制效果回看、核验退款、投诉答复、处罚留痕
   └─ RulesPage.vue        规则原文与公共资源公平性说明
```

## 已执行的验证

- `npm run build`（含 `vue-tsc --noEmit` 全量类型检查）通过，产物输出到 `dist/`。

- `npm run dev` 启动后，用 `curl` 验证首页（HTTP 200、标题正确）以及全部 `src/**`（含本轮改动的 store/engine/mock/rules 与 5 个页面/组件）经 Vite 转换后均返回 200、无报错。
- `vite preview` 托管生产构建，首页 HTTP 200、JS 产物正常加载。
- 夜间限制规则 **33 项断言冒烟测试全部通过**（`npx esbuild scripts/smoke-night.ts --bundle --platform=node --format=cjs --outfile=/tmp/smoke-night.cjs && node /tmp/smoke-night.cjs`），覆盖：
  - 违规次数→限制等级递进（1 次观察 / 2 次加倍押金 / 3 次限时段≤21:00 / 4 次暂停夜间预约）；
  - 预置夜猫子队 30 天内 2 次 → 半场押金 100 / 全场 200，普通队仍为 50/100；
  - 平台结束时间取「预约结束 / 静音截止 / 限制最晚结束」最早值（R-NOISE-3）；
  - 照明在静音截止时间自动关灯、停止计费（22:30 只计到 22:00，240 分钟而非 270）；
  - 噪声工单四要素（投诉时间/队伍/关灯时间/现场提醒）留痕、首次劝导不收费；
  - 限制生效前后投诉对比（社区端效果回看）、按日投诉趋势；
  - 端到端：受限队创建夜间预约写入限制快照、实缴押金 100、时间线含 R-NOISE-2/R-NOISE-3 公示。

说明：本项目为前端交互演示，支付、短信、真实定位等均为页面内模拟；刷新页面会重置为初始演示数据。交付物含 `Dockerfile` / `docker-compose.yml` / `nginx.conf`，本开发环境无 Docker 守护进程，镜像未在本机实际构建，配置为 node:20 构建 + nginx 托管的标准多阶段结构。
